## 已做完

### 远程 AI Provider

- 配置项：
  - `AQUAPILOT_AI_BASE_URL`：OpenAI-compatible 基址，例如 `https://api.deepseek.com/v1`、本地 `http://127.0.0.1:11434/v1`；
  - `AQUAPILOT_AI_API_KEY`：Bearer token，只从环境读，不出现在任何响应；
  - `AQUAPILOT_AI_MODEL`：模型名，默认 `gpt-4o-mini`；
  - `AQUAPILOT_AI_TIMEOUT_SECONDS`：2–120 秒，默认 20。
- `POST /api/v1/ai/explain` 把评分卡、告警（最多 8 条）与问题发给 `{base}/chat/completions`；只依据证据回答，不补 BOD/能耗/设备状态。
- 远端失败自动回退 `local-evidence`，响应带 `degraded=true` 与 `provider_error`，不静默假装远端成功。
- 新增 `GET /api/v1/ai/status`，返回 provider/model/mode/fallback，不返回 key。
- UI 的 AI 标签从硬编码改为读取该状态。

### MCP stdio 工具桥

新增 CLI：

```bash
aquapilot-v2 mcp --api http://127.0.0.1:5173 [--token <bearer>]
```

- 传输：stdio，newline-delimited JSON-RPC 2.0；实现 `initialize`、`notifications/initialized`、`ping`、`tools/list`、`tools/call`。
- 工具：
  - `aquapilot_list_experiments`
  - `aquapilot_get_experiment`
  - `aquapilot_get_experiment_report`
  - `aquapilot_run_experiment`
  - `aquapilot_explain_experiment`
  - `aquapilot_get_study`
- `run_experiment` 直接桥接 `POST /api/v1/experiments`，走同一校验、队列与幂等键；`explain_experiment` 走同一 AI Provider。
- 实机：5202 服务上 `initialize` 返回 `aquapilot-v2` 0.0.22；`tools/list` 6 个工具；`get_experiment`、`get_experiment_report` 成功；`run_experiment` 创建 `aff3c40b-dc66-455b-ac18-04d9fb274630`，随后状态 `succeeded`、progress 1.0。
- 证据：`docs/cutover/mcp-0.0.22-tools.json`。
