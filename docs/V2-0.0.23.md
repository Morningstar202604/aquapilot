# AquaPilot V2 0.0.23 验收：真实 Modbus TCP / MQTT 连接检查（fail-closed）

> 基线：0.0.22 / `c15f8b9`。本批交付 P4 的协议连接检查：Modbus TCP 与 MQTT 3.1.1 走真实 socket 与协议帧；OPC UA 明确标为未实现，不用 TCP 连通冒充会话。
> 质量门：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 全过（97 项）。

## 已做完

### CLI

```bash
aquapilot-v2 gateway-check /path/to/gateway.json --out result.json
```

- 退出码 0 仅当配置里每个适配器都 `connected=true`；任一失败退出 1，并写出完整 JSON。
- 只读检查，不写 PLC/寄存器；不扫描网段，只连配置显式给出的 endpoint。

### 配置

```json
{
  "modbus": {
    "endpoint": "127.0.0.1:15020",
    "unit": 1,
    "timeout_seconds": 2,
    "read": [
      {"point_id": "influent_flow", "register": 0, "count": 1, "scale": 10}
    ]
  },
  "mqtt": {
    "broker": "127.0.0.1:18830",
    "client_id": "aquapilot-probe",
    "timeout_seconds": 2
  },
  "opcua": {"endpoint": "opc.tcp://127.0.0.1:4840", "timeout_seconds": 2}
}
```

- Modbus：Function 03 读保持寄存器，解析 MBAP/byte count/异常；`value = raw × scale + offset`。
- MQTT：发送 MQTT 3.1.1 CONNECT（clean session、keepalive 30），等待 CONNACK 且 return code=0。
- OPC UA：返回 `mode=unsupported`、`connected=false`，错误原因为未实现 SecureChannel/Session；不把 TCP 可达当 OPC UA 已连接。

### 实机验收（本地协议双端）

- 启动本地 Modbus TCP mock，寄存器 0 返回 100；MQTT mock 返回 CONNACK 0。
- `gateway-check` 输出：Modbus `connected=true`、`value=1000`（scale 10）；MQTT `connected=true`、`client_id=aquapilot-probe`；`all_connected=true`，退出 0。
- 失败场景：Modbus 指向 `127.0.0.1:1`（拒绝连接）+ OPC UA 未实现；输出 `all_connected=false`，OPC UA `mode=unsupported`，退出 1。
- 证据：
  - `docs/cutover/gateway-check-real-modbus-mqtt.json`
  - `docs/cutover/gateway-check-failclosed.json`
- 这证明的是协议客户端与检查逻辑，不是现场 PLC 验收；没有现场端点/凭据，不冒充现场连接成功。
