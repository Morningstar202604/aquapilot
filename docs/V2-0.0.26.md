# AquaPilot V2 0.0.26 验收：服务运行时真实 OPC UA 会话

> 基线：0.0.25 / `56cd489`。本批把 OPC UA 从“明确 unsupported、拒绝拿 TCP 可达冒充会话”推进到真实二进制协议客户端的 SecureChannel / Session / Read，并接入 CLI 与服务运行时。验收对象是本机真实 OPC UA 协议双端，不是现场 PLC/SCADA 验收；只支持 `SecurityPolicy None / MessageSecurityMode None / Anonymous` 的只读会话。
> 质量门：`cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 全过（111 项）。

## 已做完

### 真实 OPC UA 客户端

- 新增 `crates/aquapilot-service/src/opcua.rs`，使用 `async-opcua 0.19` 客户端完成：GetEndpoints → OpenSecureChannel → CreateSession → ActivateSession → Read。
- 只实现匿名、无签名、无加密的 `SecurityPolicy None` / `MessageSecurityMode None`；没有把 TCP connect 当成 OPC UA 连接，也没有声称支持签名、加密、证书信任链或用户名令牌。
- `opcua.read[]` 映射 `point_id → node_id`，校验 `DataValue.status == Good`，用 `Variant::as_f64` 转数值后应用 `scale / offset`；非数字、非 Good、非有限值都判失败，不写点位。
- 连接、激活会话、单次读取都有超时；`check_config` 是一轮连接/读取/断开探测，`run` 是持久会话轮询，读取失败后由上层重连。
- PKI 目录默认 `/tmp/aquapilot-opcua-pki`，可用配置 `pki_dir` 或环境变量 `AQUAPILOT_OPCUA_PKI_DIR` 覆盖；只用于本地验收临时证书，不代表生产证书管理。

### 服务运行时

- `AQUAPILOT_GATEWAY_CONFIG` 的 `opcua` 段在服务启动后另起持久会话；`AQUAPILOT_OPCUA_POLL_SECONDS` 默认 10 s，范围 2–3600 s。
- 读取结果写回 `IndustrialHub` 点位并置 `quality=good`；未知 `point_id`、非数字或非 Good 不更新点位，累计 `bad_values`。
- `GET /api/v1/industrial/adapters` 新增 `opcua_runtime`：`state / connected / polls / bad_values / last_values / last_read_at_unix / error / security_policy / security_mode`。
- `all_connected` 同时要求协议检查、MQTT 运行时、OPC UA 运行时都通过；OPC UA 断开时即使旧协议检查仍是 true，也会 fail-closed 变 false。
- 同步 `poll_once` 只检查 Modbus/MQTT；返回的 `last_check` 显式带 `excluded: ["opcua"]` 与 `scope: "sync-adapters-excluding-async"`，避免把“同步检查未覆盖 OPC UA”误读成“OPC UA 已断开”。根 `adapters` 的 `all_connected` 已合并 OPC UA runtime。
- 断线或重连中会清空 `last_values`，不把上一轮读数伪装成当前读数。

### CLI 与界面

- `aquapilot-v2 gateway-check` 改为 async：Modbus/MQTT 同步检查后，再等待真实 OPC UA 会话探测并合并 `all_connected`；输出带 `service_version`、`excluded`、`scope`。
- UI 工业网关 chip 显示 `opcua · 3 · N poll`；遥测条在只有 OPC UA 时显示 OPC UA 的 DO / KLa / 进水流量，不再回落到默认 MQTT 数值。
- 截图：`docs/screenshots/v2-ui-opcua-session.png`（页面版本 `v0.0.26`，`opcua · 3 · 28 poll`，DO 2.100 mg/L、KLa 8.000 1/h、进水流量 1000.000 m³/h）。

### 配置示例

```json
{
  "opcua": {
    "endpoint": "opc.tcp://127.0.0.1:4841",
    "timeout_seconds": 5,
    "pki_dir": "/tmp/aquapilot-opcua-pki",
    "read": [
      {"point_id": "aerobic.do", "node_id": "ns=2;s=DO", "scale": 1.0, "offset": 0.0},
      {"point_id": "aerobic.kla", "node_id": "ns=2;s=KLa"},
      {"point_id": "influent.flow", "node_id": "ns=2;s=Flow"}
    ]
  }
}
```

- 只连配置显式给出的 `opc.tcp://` 端点，不扫网、不浏览节点树；本批不做 Browse / Write / Subscription。
- `scale` 不能为 0，`offset` 必须有限；映射非法时 CLI 与服务都 fail-closed。

### 实机验收（本机真实 OPC UA 双端）

- 本地 Python `asyncua 2.1.0` 服务 `127.0.0.1:4841`，节点 `ns=2;s=DO`、`ns=2;s=KLa`、`ns=2;s=Flow`，每 2 s 更新 DO / Flow。
- 服务 `127.0.0.1:5205`，配置 `/tmp/gateway-service-026-opcua.json`，DB `/tmp/aquapilot-opcua25.sqlite`；`AQUAPILOT_GATEWAY_POLL_SECONDS=3600` 隔离 Modbus/MQTT，`AQUAPILOT_OPCUA_POLL_SECONDS=2`。
- 运行时 `all_connected=true`、`opcua_runtime.state=connected`；两次采样相隔 2 s：DO 2.0 → 2.1 mg/L、KLa 8.0 1/h、进水流量 1020 → 1000 m³/h，三点 `quality=good`。证据：`docs/cutover/gateway-runtime-opcua-0.0.26.json`（`polls=10`）。
- CLI 对同一配置 exit 0：`all_connected=true`、`mode=real-opcua-session`，读到 DO 2.0、KLa 8.0、Flow 1010；`service_version=0.0.26`。证据：`docs/cutover/gateway-check-opcua-0.0.26.json`。
- 失败场景：停掉本地 OPC UA server 5 s，服务 `opcua_runtime.state=error`、`all_connected=false`、`last_values=[]`；CLI 对同一端点 exit 1、`all_connected=false`、`Connected=false`。证据：`docs/cutover/gateway-runtime-opcua-failclosed-0.0.26.json`、`docs/cutover/gateway-check-opcua-failclosed-0.0.26.json`。
- 恢复场景：重启本地 server 后 11 s 内恢复 `opcua_state=connected`、`all_connected=true`，`polls` 继续增长到 26；恢复记录在同一份 fail-closed 证据里。

## 未完成

- 现场验收：没有现场 PLC/SCADA 的 OPC UA 端点、节点表、证书或账号；本批只证明本机真实协议双端，不能宣称现场已接入。
- 安全能力：只支持 `None / None / Anonymous`；未做 Sign / SignAndEncrypt、证书信任链、用户名/证书身份认证、节点权限与审计。
- 只读：未做 Browse、Write、Subscription；写入仍只有 Modbus `write` 映射，OPC UA 不承接设定点下发。
- MQTT 仍只做匿名 QoS 0；TLS、认证、QoS1/2、保留/遗嘱消息未接。
- 24 h soak：`docs/soak-24h-summary.json` 不存在，`completed_24h=false`。
- Cutover 仍 **NO-GO**：BOD5 缺失、30 d COD/SS/TP 未过、24 h soak 未完成。

## 结论

0.0.26 关闭了“OPC UA 只有 unsupported 文案、没有真实会话”的缺口：CLI 与服务运行时现在都走真实 SecureChannel / Session / Read，断线可见且 fail-closed，UI 不再显示默认 MQTT 假遥测。它没有关闭现场设备验收、OPC UA 安全策略/认证、OPC UA 写入/订阅、24 h soak 或 Cutover Gate。
