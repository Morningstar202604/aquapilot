# 运行手册（Runbook）

> 面向运维与值班人员：日常巡检看什么、出问题查哪里、怎么恢复。
> 与 `DEPLOYMENT.md` 的分工：那边讲「怎么装」，这边讲「装好之后怎么运营」。

---

## 一、日常巡检（每班一次，5 分钟）

按顺序检查三个信号，全部正常即通过：

| 顺序 | 检查 | 在哪看 | 正常标准 |
|---|---|---|---|
| 1 | 服务存活 | 顶栏连接点（绿=正常） | 绿色且「正在接收仿真数据」 |
| 2 | 仿真推进 | 顶栏仿真时钟 | 数字在走（暂停时除外） |
| 3 | 系统自检 | 「自检」页签 | 无 error 级条目 |

**异常处置速查**：

| 症状 | 先查 | 处置 |
|---|---|---|
| 连接点红色 | 服务进程是否存活 | `curl http://<host>:5173/api/health` 返回 200 则是网络问题，否则重启服务 |
| 仿真时钟不走 | 「自检」页签的 tick 错误计数 | tick 失败会自动暂停并广播通知；按通知处理或点「重置」 |
| 自检有 error | 自检条目的 `action` 字段 | 每条自检都写了下一步动作，照做即可 |

## 二、深度健康检查（接入监控时用）

```bash
# 存活探针：进程能响应即 200（给 restart 策略用）
curl http://127.0.0.1:5173/api/health

# 就绪探针：仿真停摆或持久化故障时返回 503（给告警用）
curl 'http://127.0.0.1:5173/api/health?deep=1'
```

Prometheus 指标在 `/api/metrics`（文本格式）或 `/api/metrics?format=json`。
建议的告警规则见 `docs/SLO.md`。

## 三、数据与备份

| 数据 | 位置 | 丢失影响 |
|---|---|---|
| 决策 / 告警 / 回放快照 | `data/aquapilot.db`（SQLite） | 历史记录丢失，仿真不受影响 |
| 工艺拓扑（编排文档） | `data/topology.json` + `data/topology-history.json` | 回到默认厂，需重新编排 |
| 模型 / Agent 配置 | `data/llm-config.json`、`data/agent-config.json` | 需重新配置 |

**备份**（`data/` 整体即可，SQLite 备份脚本会先 flush 再 VACUUM INTO 保证一致性）：

```bash
npm run backup -- create --db data/aquapilot.db --out backups/aquapilot-$(date +%Y%m%d).db
npm run backup -- restore --from backups/aquapilot-20260101.db --db data/aquapilot.db --yes
```

## 四、接入一座新厂（Onboarding 清单）

从零到可运行，按顺序 6 步：

1. **绘制工艺**：「工艺编排」视图拖出该厂的池子与管线（进水 → 生物池 → 二沉池 → 排放），主干线必须是 `influent` 物流。
2. **填几何参数**：每个池子双击检视器填容积；二沉池填面积与深度。校验器会实时提示阻断项（环路 / 缺端口 / 主线断链）。
3. **应用到仿真**：点「应用」。服务端会重建求解器并预热 30 天（约 1 秒），预热完成即显示稳态出水。
4. **（可选）加载真实进水**：「进水」页签上传该厂的历史 CSV（格式见面板内说明）。先看质量报告，有 error 级问题先修数据再应用。
5. **（可选）校准模型**：「校准」页签先跑可辨识性分析（约 40 秒），确认哪些参数能被数据约束，再启动完整标定（2–3 分钟）。标定结果**不会自动生效**，需人工确认。
6. **设定护栏**：「设置 → Agent」配置 AI 允许调节哪些控制量、单步幅度、是否需要人工确认。接入真实厂建议先开「人工确认」跑一周。

## 五、常见问题

**Q：AI 的建议会直接执行吗？**
默认会（aiEnabled 开启时），但有三层约束：允许调节白名单、单步幅度限幅、人工调整后 30 分钟静默期。在「设置 → Agent」里可改为「只建议不执行」。

**Q：出水数据与厂里实测对不上？**
先走「校准」链路（见上）。如果标定后仍偏差大，检查进水数据质量（「进水」页签的质量报告），进水错则一切皆错。

**Q：改了拓扑/参数后能回退吗？**
能。「工艺编排 → 版本历史」列出最近 20 版，可一键回滚；服务重启也会恢复上次保存的拓扑。

**Q：如何完全重置仿真？**
顶栏「重置」按钮：仿真时钟归零、重新预热，但**保留**拓扑与累计历史数据。

**Q：多个人同时看会冲突吗？**
所有客户端共享同一仿真状态，一人改控制所有人可见（这是特性不是缺陷）。权限用三档令牌区分（见 `docs/API.md` 的 Roles 一节）：值班大屏发 viewer 令牌，防止误触。
